## 1. 项目概述

### 1.1 项目背景

在快节奏的现代生活中，日程管理已成为每个人的日常需求。传统日历工具依赖手动输入，在驾驶、烹饪、运动等场景下操作不便。VoiceCal 通过**语音优先（Voice-First）**的交互范式，让用户"动口不动手"即可完成日程管理。

### 1.2 核心价值

| 价值点   | 说明               |
| ----- | ---------------- |
| 效率提升  | 语音操作比手动输入快 3-5 倍 |
| 场景解放  | 支持 hands-free 操作 |
| 智能辅助  | AI 驱动的冲突检测与排期优化  |
| 多模态反馈 | 语音 + 视觉 + 动画三重反馈 |
| 情感温度  | 中国式节日关怀，让日历有温度   |

### 1.3 本机环境

```

```

## 4. 创新点

### 4.1 流式语音实时识别

语音采集 → WebSocket 二进制流 → 百度云 ASR → 实时回显识别文本。延迟 <500ms。

### 4.2 多模态确认闭环

操作后通过 **语音播报 + 日历占位块 + 确认按钮** 三重反馈，用户确认后才执行。

### 4.3 NLU 双引擎兜底

LLM 解析（主力）+ 规则引擎（兜底）+ 交互澄清，覆盖 99%+ 意图识别。

### 4.4 智能时间表达解析

支持绝对时间、相对时间、模糊时间、周期时间多种自然语言表达。

### 4.5 智能冲突检测

自动检测时间重叠 → 冲突分级（完全/部分/紧密相邻）→ 提示用户。

### 4.6 中国式浪漫·情感化节日关怀

用户**首次在节日当天安排日程**时，自动送上祝福 + 传统习俗建议 + 快捷动作。

| 场景    | 示例                              |
| ----- | ------------------------------- |
| 母亲节   | "今天是母亲节 🌸，记得给妈妈打个电话或回家陪她吃顿饭哦~" |
| 中秋节   | "月圆人团圆 🏮，今晚记得回家陪家人吃月饼赏月哦~"     |
| 清明节   | "追思先人，珍惜当下 🌧️，需要帮您安排扫墓时间吗？"    |
| 二十四节气 | "今天立冬了 🍲，记得吃饺子保暖哦~"            |

**技术实现**：前端 JSON 硬编码节日库 → 创建事件时判断是否首次 → 匹配节日 → TTS + 弹窗。

## 5. 数据库设计

### 5.1 核心表结构

```sql
-- ============================================
-- 用户表
-- ============================================
CREATE TABLE `user` (
  `id` BIGINT PRIMARY KEY AUTO_INCREMENT,
  `username` VARCHAR(50) NOT NULL UNIQUE,
  `password` VARCHAR(255) NOT NULL COMMENT 'BCrypt 加密',
  `nickname` VARCHAR(50),
  `email` VARCHAR(100),
  `preferences` JSON COMMENT '偏好设置',
  `status` TINYINT DEFAULT 1 COMMENT '1:正常 0:禁用',
  `created_at` DATETIME DEFAULT CURRENT_TIMESTAMP,
  `updated_at` DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  INDEX `idx_username` (`username`),
  INDEX `idx_email` (`email`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='用户表';

-- ============================================
-- 日历事件表（核心表）
-- ============================================
CREATE TABLE `calendar_event` (
  `id` BIGINT PRIMARY KEY AUTO_INCREMENT,
  `user_id` BIGINT NOT NULL,
  `title` VARCHAR(200) NOT NULL COMMENT '事件标题',
  `description` TEXT COMMENT '事件描述',
  `start_time` DATETIME NOT NULL COMMENT '开始时间',
  `end_time` DATETIME NOT NULL COMMENT '结束时间',
  `all_day` TINYINT(1) DEFAULT 0 COMMENT '是否全天事件',
  `location` VARCHAR(200) COMMENT '地点',
  `category` VARCHAR(50) DEFAULT 'personal' COMMENT 'personal/work/family/other',
  `color` VARCHAR(20) DEFAULT '#409EFF',
  `priority` TINYINT DEFAULT 5 COMMENT '优先级 1-10',
  `reminder_minutes` INT DEFAULT 15 COMMENT '提前提醒分钟数',
  `status` VARCHAR(20) DEFAULT 'active' COMMENT 'active/cancelled/completed',
  `created_at` DATETIME DEFAULT CURRENT_TIMESTAMP,
  `updated_at` DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  INDEX `idx_user_time` (`user_id`, `start_time`),
  INDEX `idx_user_status` (`user_id`, `status`),
  INDEX `idx_start_time` (`start_time`),
  FOREIGN KEY (`user_id`) REFERENCES `user`(`id`) ON DELETE CASCADE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='日历事件表';

-- ============================================
-- 语音命令日志表
-- ============================================
CREATE TABLE `voice_command_log` (
  `id` BIGINT PRIMARY KEY AUTO_INCREMENT,
  `user_id` BIGINT NOT NULL,
  `session_id` VARCHAR(100),
  `raw_audio_text` TEXT COMMENT 'ASR 识别文本',
  `intent` VARCHAR(50) COMMENT 'CREATE/QUERY/UPDATE/DELETE',
  `entities` JSON COMMENT '提取实体',
  `confidence` DECIMAL(3,2) COMMENT '置信度',
  `command_result` VARCHAR(20) COMMENT 'success/failed',
  `response_text` TEXT COMMENT '系统响应',
  `duration_ms` INT COMMENT '处理耗时',
  `created_at` DATETIME DEFAULT CURRENT_TIMESTAMP,
  INDEX `idx_user_session` (`user_id`, `session_id`),
  INDEX `idx_created_at` (`created_at`),
  FOREIGN KEY (`user_id`) REFERENCES `user`(`id`) ON DELETE CASCADE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='语音命令日志表';
```

## 6. 接口设计（统一 API 文档）

### 6.1 RESTful API

| 方法     | 路径                                    | 说明       | 请求体                                     | 响应                                |
| ------ | ------------------------------------- | -------- | --------------------------------------- | --------------------------------- |
| POST   | `/api/auth/register`                  | 用户注册     | `{username, password, nickname, email}` | `ApiResponse<UserVO>`             |
| POST   | `/api/auth/login`                     | 用户登录     | `{username, password}`                  | `ApiResponse<{token, user}>`      |
| GET    | `/api/events?start=&end=`             | 按时间范围查询  | Query: start, end                       | `ApiResponse<List<EventVO>>`      |
| GET    | `/api/events/today`                   | 查询今日事件   | -                                       | `ApiResponse<List<EventVO>>`      |
| GET    | `/api/events/{id}`                    | 查询事件详情   | -                                       | `ApiResponse<EventVO>`            |
| POST   | `/api/events`                         | 创建事件     | `EventCreateRequest`                    | `ApiResponse<EventVO>`            |
| PUT    | `/api/events/{id}`                    | 更新事件     | `EventUpdateRequest`                    | `ApiResponse<EventVO>`            |
| DELETE | `/api/events/{id}`                    | 删除事件     | -                                       | `ApiResponse<Void>`               |
| POST   | `/api/voice/asr`                      | 语音识别     | `{audio: base64}`                       | `ApiResponse<{text, confidence}>` |
| POST   | `/api/voice/nlu`                      | NLU 意图解析 | `{text}`                                | `ApiResponse<NluResult>`          |
| POST   | `/api/voice/command`                  | 语音指令全链路  | `{audio: base64}`                       | `ApiResponse<CommandResult>`      |
| GET    | `/api/schedule/conflicts?start=&end=` | 冲突检测     | Query                                   | `ApiResponse<List<ConflictVO>>`   |

### 6.2 统一响应格式

```json
{
  "code": 200,
  "message": "success",
  "data": {},
  "timestamp": 1716998400000
}
```

| code | 含义    |
| ---- | ----- |
| 200  | 成功    |
| 400  | 参数错误  |
| 401  | 未认证   |
| 403  | 无权限   |
| 404  | 资源不存在 |
| 500  | 服务器错误 |

### 6.3 WebSocket 接口

| 端点             | 方向      | 消息类型   | 说明                      |
| -------------- | ------- | ------ | ----------------------- |
| `/ws/voice`    | 客户端→服务端 | Binary | 音频流（PCM 16kHz, 100ms/帧） |
| `/ws/voice`    | 服务端→客户端 | Text   | ASR 识别结果                |
| `/ws/calendar` | 服务端→客户端 | Text   | 事件变更推送 + 提醒             |

**WebSocket 消息协议**：

```json
// 服务端 → 客户端：ASR 结果
{"type": "ASR_RESULT", "interim": true, "text": "明天下午3点开会", "confidence": 0.95}

// 服务端 → 客户端：ASR 最终结果
{"type": "ASR_FINAL", "text": "明天下午3点开会", "nlu": {"intent": "CREATE", "title": "开会", ...}}

// 服务端 → 客户端：事件变更
{"type": "EVENT_CHANGED", "action": "CREATE", "event": {"id":1, "title":"开会", ...}}

// 服务端 → 客户端：节日关怀
{"type": "FESTIVAL_GREETING", "festival": "母亲节", "greeting": "...", "suggestions": [...]}

// 服务端 → 客户端：提醒
{"type": "REMINDER", "eventId": 1, "title": "项目评审", "startTime": "..."}

// 心跳
{"type": "PING"} ↔ {"type": "PONG"}
```

## 9. 开发规范

### 9.1 命名规范

| 层级            | 规范                       | 示例                   |
| ------------- | ------------------------ | -------------------- |
| 后端 Controller | XxxController            | `EventController`    |
| 后端 Service    | XxxService               | `EventService`       |
| 后端 Repository | XxxRepository            | `EventRepository`    |
| 后端 DTO        | XxxRequest / XxxResponse | `EventCreateRequest` |
| 前端组件          | PascalCase               | `VoiceButton.vue`    |
| 前端 Composable | useXxx                   | `useVoice.ts`        |
| API 路径        | 小写 + 复数                  | `/api/events`        |
| 数据库表          | 小写 + 下划线 + 复数            | `voice_command_log`  |

### 9.2 后端规范

- 构造器注入
- 统一 SLF4J 日志
- @Valid 参数校验
- @Transactional 事务管理
- @ControllerAdvice 全局异常处理

### 9.3 前端规范

- `<script setup>` 语法
- Composable 单一职责
- Props 类型声明接口
- 组件数据流单向

### 9.4 AI Agent 协作规范

| 阶段  | 交给 Agent 生成                             | 人工负责      |
| --- | --------------------------------------- | --------- |
| 数据库 | DDL + 初始化 SQL                           | 审核表结构合理性  |
| 后端  | Entity/Repository/Service/Controller 代码 | 审核业务逻辑正确性 |
| 前端  | 组件 + Composable + Store                 | 审核交互逻辑    |
| 语音  | WebSocket Handler + 录音 + ASR 集成         | 审核音频流处理   |
| CR  | 代码质量扫描 + 问题标注                           | 确认修正方案    |

## 10. 风险与应对

| 风险             | 等级  | 应对策略                          |
| -------------- | --- | ----------------------------- |
| 2 天时间极其紧张      | 高   | Agent 生成+人工审核并行；先跑通主链路，细节后续迭代 |
| 百度云 ASR 配置耗时   | 中   | 提前注册好账号；先 Mock ASR 保证开发不阻塞    |
| WebSocket 联调问题 | 中   | 先使用 WebSocket 在线测试工具验证后端      |
| 前后端接口不一致       | 低   | 先统一 API 文档再并行开发               |
| 浏览器录音兼容性       | 低   | 使用 RecordRTC 封装，回退到文本输入       |
| Agent 生成代码质量问题 | 中   | 每天结束前集中 Code Review           |

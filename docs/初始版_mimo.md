## 📋 一、项目概述

### 1.1 项目背景

随着 AI 技术的快速发展，语音交互已成为提升效率的重要方式。传统日历工具依赖"点击+输入"的操作模式，在驾驶、烹饪、运动等 hands-free 场景下使用不便。本项目旨在开发一个以语音为核心交互方式的智能日历工具，让用户通过自然语言即可完成日程管理。

### 1.2 项目目标

- 实现语音添加/删除/查看/修改日程事件
- 支持自然语言时间解析（如"明天下午3点"、"下周三"）
- 提供多模态反馈（语音播报 + 可视化面板）
- 实现智能冲突检测与提醒
- 打造流畅、低延迟的语音交互体验

### 3.2 本项目创新点

#### 创新点 1：流式语音实时识别

**传统方式**：用户说完 → 等待识别 → 返回结果（延迟 2-3 秒）

**创新方式**：边说边识别，实时显示中间结果（延迟 <500ms）

```
技术实现：
┌─────────────┐    音频流     ┌─────────────┐    流式识别    ┌─────────────┐
│   前端录音   │ ──────────→ │  WebSocket  │ ──────────→ │  云语音API  │
│  (200ms/片) │             │   Server    │             │  (流式模式) │
└─────────────┘             └─────────────┘             └─────────────┘
                                  │
                                  │ 实时推送中间结果
                                  ↓
                            ┌─────────────┐
                            │  前端实时显示 │
                            │  识别文本    │
                            └─────────────┘
```

**用户体验提升**：

- 说话过程中即可看到识别结果
- 发现错误可立即纠正
- 整体交互延迟降低 60%+

#### 创新点 2：多轮对话式日程管理

**传统方式**：每次语音命令都是独立的单轮交互

**创新方式**：支持上下文感知的多轮对话

```
示例对话：
用户：添加明天下午的会议
系统：好的，请问会议时间和主题是什么？
用户：3点，项目评审
系统：已添加"项目评审"，明天下午3点。需要设置提醒吗？
用户：提前15分钟提醒
系统：好的，已设置提前15分钟提醒。
```

**技术实现**：

- 前端维护对话上下文（最近 3 轮）
- 后端 NLU 引擎解析省略信息
- 状态机管理对话流程

#### 创新点 3：智能时间表达解析

**传统方式**：只支持标准时间格式（如"2024-03-15 15:00"）

**创新方式**：支持自然语言时间表达

```
支持的时间表达：
├── 绝对时间
│   ├── "明天下午3点"
│   ├── "下周五上午10点半"
│   └── "3月15号"
├── 相对时间
│   ├── "三天后"
│   ├── "下周"
│   └── "月底"
├── 模糊时间
│   ├── "找个时间和小王吃饭"
│   └── "这周有空的时候"
└── 周期时间
    ├── "每周一上午9点"
    └── "每月1号"
```

**技术实现**：

- 自定义时间解析引擎
- 基于当前日期的动态计算
- 模糊时间 → 建议具体时间

#### 创新点 4：多模态融合反馈

**传统方式**：只有视觉反馈（弹窗、页面跳转）

**创新方式**：语音 + 视觉 + 动画 三重反馈

```
反馈矩阵：
┌─────────────┬─────────────┬─────────────┐
│   操作类型   │   语音反馈   │   视觉反馈   │
├─────────────┼─────────────┼─────────────┤
│ 添加成功    │ "已添加..."  │ 日历高亮 + ✅│
│ 删除确认    │ "确定删除?"  │ 弹窗确认框   │
│ 冲突检测    │ "检测到冲突" │ 红色标记 ⚠️  │
│ 查看日程    │ 语音播报列表 │ 列表视图展开 │
└─────────────┴─────────────┴─────────────┘
```

#### 创新点 5：本地 NLU + 云端 ASR 混合架构

**传统方式**：所有处理都在云端，依赖网络

**创新方式**：

- **ASR（语音识别）**：云端处理，准确率高
- **NLU（自然语言理解）**：本地处理，响应快，隐私好

```
架构优势：
├── 响应速度：NLU 本地处理 <50ms
├── 隐私保护：日程内容不上传云端
├── 离线能力：基础命令可离线使用
└── 成本控制：减少云端调用次数
```

### 5.4 数据库设计

```sql
-- 用户表
CREATE TABLE `user` (
  `id` BIGINT PRIMARY KEY AUTO_INCREMENT,
  `username` VARCHAR(50) NOT NULL,
  `password` VARCHAR(255) NOT NULL,
  `nickname` VARCHAR(50),
  `phone` VARCHAR(20),
  `created_at` DATETIME DEFAULT CURRENT_TIMESTAMP,
  `updated_at` DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
);

-- 日历事件表
CREATE TABLE `calendar_event` (
  `id` BIGINT PRIMARY KEY AUTO_INCREMENT,
  `user_id` BIGINT NOT NULL,
  `title` VARCHAR(200) NOT NULL,
  `description` TEXT,
  `start_time` DATETIME NOT NULL,
  `end_time` DATETIME NOT NULL,
  `location` VARCHAR(200),
  `category` VARCHAR(50) DEFAULT 'personal',
  `color` VARCHAR(20) DEFAULT '#409EFF',
  `is_all_day` BOOLEAN DEFAULT FALSE,
  `repeat_rule` VARCHAR(50),
  `reminder_minutes` INT DEFAULT 15,
  `status` VARCHAR(20) DEFAULT 'active',
  `created_at` DATETIME DEFAULT CURRENT_TIMESTAMP,
  `updated_at` DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  INDEX `idx_user_time` (`user_id`, `start_time`)
);

-- 重复事件规则表
CREATE TABLE `repeat_rule` (
  `id` BIGINT PRIMARY KEY AUTO_INCREMENT,
  `event_id` BIGINT NOT NULL,
  `rule_type` VARCHAR(20) NOT NULL,
  `interval` INT DEFAULT 1,
  `days_of_week` VARCHAR(20),
  `end_date` DATETIME,
  `max_occurrences` INT
);

-- 提醒表
CREATE TABLE `reminder` (
  `id` BIGINT PRIMARY KEY AUTO_INCREMENT,
  `event_id` BIGINT NOT NULL,
  `remind_at` DATETIME NOT NULL,
  `is_sent` BOOLEAN DEFAULT FALSE,
  `created_at` DATETIME DEFAULT CURRENT_TIMESTAMP
);
```

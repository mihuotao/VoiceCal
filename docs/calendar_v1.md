# VoiceCal - 智能语音日历管理系统

## 项目架构设计文档 v1.0

---

## 📌 一、项目简介

### 1.1 项目背景

在快节奏的现代生活中，日程管理已成为每个人的日常需求。传统日历工具依赖手动输入，效率低下，尤其在驾驶、烹饪、运动等场景下操作不便。VoiceCal 旨在通过语音交互革新日程管理体验，让用户"动口不动手"即可完成日程安排。

### 1.2 项目定位

VoiceCal 是一款基于语音交互的智能日历管理系统，通过集成云语音服务与 AI 技术，实现语音创建、查询、修改、删除日程，并提供智能冲突检测与排期建议，帮助用户高效管理时间。

### 1.3 核心价值

| 价值点       | 说明                         |
| --------- | -------------------------- |
| **效率提升**  | 语音操作比手动输入快 3-5 倍           |
| **场景解放**  | 支持 hands-free 操作，适用于多种生活场景 |
| **智能辅助**  | AI 驱动的冲突检测与排期优化            |
| **多模态反馈** | 语音 + 视觉双重反馈，信息传达更准确        |

## 🏗️ 二、系统架构设计

### 2.1 整体架构

VoiceCal 采用前后端分离的单体架构，通过 WebSocket 实现实时语音通信，结合 Redis 缓存提升性能，使用 Docker 容器化部署保障环境一致性。

```
┌─────────────────────────────────────────────────────────────────────┐
│                          用户终端层                                  │
│                     浏览器 (Chrome / Edge)                          │
│  ┌─────────────┐    ┌─────────────┐    ┌─────────────┐             │
│  │  语音交互   │    │  日历展示   │    │  消息通知   │             │
│  └─────────────┘    └─────────────┘    └─────────────┘             │
└─────────────────────────────────────────────────────────────────────┘
                                  │
                           HTTPS / WSS
                                  ▼
┌─────────────────────────────────────────────────────────────────────┐
│                          接入层                                     │
│                    Nginx (反向代理 + SSL)                           │
└─────────────────────────────────────────────────────────────────────┘
                                  │
                                  ▼
┌─────────────────────────────────────────────────────────────────────┐
│                        应用服务层                                    │
│               Spring Boot 3.2 (单体应用)                           │
│  ┌───────────────────────────────────────────────────────────────┐  │
│  │  接口层: RESTful API + WebSocket Endpoint                    │  │
│  ├───────────────────────────────────────────────────────────────┤  │
│  │  业务层: 日历服务 / 语音服务 / NLU服务 / 排期服务             │  │
│  ├───────────────────────────────────────────────────────────────┤  │
│  │  数据层: JPA + Redis Cache                                   │  │
│  └───────────────────────────────────────────────────────────────┘  │
└─────────────────────────────────────────────────────────────────────┘
                    │                    │                    │
                    ▼                    ▼                    ▼
          ┌─────────────┐    ┌─────────────┐    ┌─────────────┐
          │    MySQL    │    │    Redis    │    │  百度云API  │
          │   持久化    │    │    缓存     │    │  语音服务   │
          └─────────────┘    └─────────────┘    └─────────────┘
```

### 2.2 架构分层说明

| 层次        | 职责               | 技术选型                  |
| --------- | ---------------- | --------------------- |
| **用户终端层** | 语音采集、日历展示、结果反馈   | Vue 3 + Web Audio API |
| **接入层**   | 请求转发、负载均衡、SSL 终止 | Nginx                 |
| **应用服务层** | 业务逻辑处理、语音识别调度    | Spring Boot 3.2       |
| **数据层**   | 数据持久化、缓存加速、语音服务  | MySQL + Redis + 百度云   |

### 2.3 部署架构

采用 Docker Compose 容器化部署，实现一键启动、环境隔离、易于扩展：

```
Docker Compose 编排
├── nginx        :80/:443    反向代理
├── frontend     :5173       Vue 3 前端
├── backend      :8080       Spring Boot 后端
├── mysql        :3306       数据库
└── redis        :6379       缓存服务
```

### 4.2 模块详细说明

#### 4.2.3 智能分析模块

**模块职责**：提供冲突检测、智能排期、时间解析等 AI 能力。

**核心功能**：

| 功能   | 说明               |
| ---- | ---------------- |
| 冲突检测 | 检测新事件与已有事件的时间重叠  |
| 冲突分级 | 区分完全冲突、部分冲突、紧密相邻 |
| 智能排期 | 根据优先级和空闲时间自动安排日程 |
| 时间解析 | 理解自然语言时间表达       |

**冲突检测算法**：

```
输入: 新事件 (startTime, endTime)
输出: 冲突列表 + 冲突级别

检测逻辑:
1. 查询同一用户的所有活跃事件
2. 筛选时间重叠的事件 (existing.start < new.end AND existing.end > new.start)
3. 计算重叠时长，划分冲突级别
4. 返回冲突详情与解决建议
```

**智能排期算法**：

```
输入: 待安排事件列表 + 时间范围
输出: 排期方案 + 评分

排期逻辑:
1. 收集约束条件（已有日程、用户偏好）
2. 生成可用时间段
3. 按优先级排序待安排事件
4. 匹配最优时间段
5. 检测并解决冲突
6. 生成多个备选方案
7. 计算方案评分
```

## 💡 五、创新点说明

### 5.1 创新点一：流式语音实时识别

**创新描述**：采用流式语音识别技术，实现"边说边识别"，用户说话过程中即可实时看到识别结果，大幅提升交互流畅度。

**技术实现**：

- 前端通过 MediaRecorder API 每 200ms 采集一帧音频
- 通过 WebSocket 将音频流实时传输至后端
- 后端调用百度云流式 ASR API，边接收边识别
- 识别中间结果通过 WebSocket 实时推送回前端

**创新价值**：

- 交互延迟从传统方案的 2-3 秒降低至 <500ms
- 用户可实时看到识别结果，发现错误可立即纠正
- 提供更自然、更流畅的语音交互体验

### 5.2 创新点二：自然语言时间解析引擎

**创新描述**：自研时间解析引擎，支持多种自然语言时间表达，用户无需记忆固定格式，用日常说话方式即可表达时间。

**支持的时间表达类型**：

| 类型   | 示例                           |
| ---- | ---------------------------- |
| 绝对时间 | "明天下午3点"、"下周五上午10点半"、"3月15号" |
| 相对时间 | "三天后"、"下周"、"月底"              |
| 模糊时间 | "找个时间和小王吃饭"、"这周有空的时候"        |
| 周期时间 | "每周一上午9点"、"每月1号"             |

**技术实现**：

- 基于规则引擎的时间表达式解析
- 结合当前日期的动态时间计算
- 上下文感知的模糊时间理解
- 时间歧义消解与确认机制

**创新价值**：

- 降低用户学习成本，自然表达即可
- 支持更灵活的时间描述
- 提升语音交互的自然度

### 5.3 创新点三：智能冲突检测与排期优化

**创新描述**：集成智能冲突检测与排期优化引擎，自动识别日程冲突并提供最优排期建议，帮助用户高效安排时间。

**技术实现**：

- 多维度冲突检测：时间冲突、地点冲突、紧密相邻
- 冲突分级机制：完全冲突、部分冲突、潜在冲突
- 基于优先级的智能排期算法
- 多备选方案生成与评分

**创新价值**：

- 避免日程冲突，减少时间管理失误
- 自动化排期，节省用户决策时间
- 智能推荐最优时间安排

### 5.4 创新点四：多模态融合反馈系统

**创新描述**：采用语音 + 视觉 + 动画三重反馈机制，确保信息传达准确、用户体验丰富。

**技术实现**：

- 语音反馈：TTS 播报操作结果
- 视觉反馈：日历面板实时更新、状态图标
- 动画反馈：过渡动画、高亮效果

**反馈矩阵**：

| 操作   | 语音反馈     | 视觉反馈    | 动画反馈   |
| ---- | -------- | ------- | ------ |
| 添加成功 | "已添加..." | 日历显示新事件 | 事件高亮闪烁 |
| 删除确认 | "确定删除?"  | 弹窗确认框   | 确认框弹出  |
| 冲突检测 | "检测到冲突"  | 红色警告标记  | 警告动画   |
| 查看日程 | 语音播报列表   | 列表视图展开  | 列表滑入   |

**创新价值**：

- 多感官通道确保信息传达
- 丰富的交互反馈提升用户体验
- 适应不同使用场景的需求

### 5.5 创新点五：Redis 多级缓存架构

**创新描述**：设计三级缓存策略，针对不同数据特点设置差异化缓存策略，最大化缓存命中率。

**技术实现**：

| 缓存层级   | 数据类型       | TTL  | 策略        |
| ------ | ---------- | ---- | --------- |
| L1 热点层 | 今日/本周日程    | 5分钟  | 高频访问，短时缓存 |
| L2 业务层 | 月度日程、冲突检测  | 30分钟 | 中频访问，中期缓存 |
| L3 持久层 | 用户偏好、NLU历史 | 24小时 | 低频变化，长期缓存 |

**创新价值**：

- 减少数据库查询压力
- 提升系统响应速度
- 降低云 API 调用成本

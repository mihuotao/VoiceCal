### 2.2 创新点详析

#### 创新 1：语音优先交互范式

**背景**: 现有日历工具（Google Calendar、Outlook 等）以点击/触摸为核心交互，语音仅作为辅助输入通道。Google Assistant 虽然支持语音创建事件，但必须先唤醒、再说出完整指令，体验割裂。

**本方案**: 打开页面即进入"语音就绪"状态，用户可以直接说话。系统自动判断是命令（"创建明天下午3点会议"）还是查询（"这周五有什么安排"）。

**实现关键**:

- 页面加载后自动初始化录音上下文（请求麦克风权限）
- 常驻"语音唤醒"按钮（大按钮 + 呼吸灯动效）
- 点击即说，松手即识别

#### 创新 2：多模态确认闭环

**背景**: 纯语音助手的最大痛点是"不可见"——用户不知道系统是否理解正确，误操作难以挽回。

**本方案**: 每次语音操作后，系统通过 **3 种通道**同步反馈：

```
用户: "创建明天下午3点会议"

通道1 — 可视面板:  日历上立即出现一个灰色占位块（"明天 15:00 会议"）
通道2 — 语音播报:  "您要创建『会议』，明天下午3点到4点，对吗？"
通道3 — 操作按钮:  显示「确认✓」「取消✗」「重说🔄」

用户: "确认"

→ 占位块变彩色，语音播报"已创建", WebSocket 同步到所有设备
```

**价值**: 解决了语音交互"看不见、不放心"的核心信任问题。

#### 创新 3：NLU 双引擎兜底架构

**架构**:

```
语音 → ASR(文字)

          ┌──────────┐
          │  LLM 解析  │ ← 主力引擎（GPT-4o / 通义千问）
          └─────┬────┘
                │ 置信度 ≥ 0.8 → 直接输出
                │ 置信度 < 0.8 → 触发兜底
                │
          ┌─────▼────┐
          │ 规则引擎   │ ← 正则 + 关键词匹配
          └─────┬────┘
                │
          ┌─────▼────┐
          │ 交互澄清   │ ← "您是希望创建还是查询？"
          └──────────┘
```

**优势**:

- LLM 覆盖 90%+ 的自然表达
- 规则引擎零延迟、零成本兜底
- 交互式澄清覆盖边界情况
- 三者组合实现 99%+ 的意图识别成功率

#### 创新 4：实时语音提醒推送

**技术链路**:

```
Spring @Scheduled(每分钟扫描)
  → 查询 events 表 (reminder_time <= now AND reminded = false)
  → WebSocket.send(reminderMessage)
  → 前端收到消息
    → 弹窗显示事件详情
    → Web Speech Synthesis API 语音播报
    → 标记已提醒
```

**差异优势**:

- 无需 App 后台常驻（Web 端提醒）
- 支持自定义提醒语调（温和/紧急/幽默）
- 支持"再提醒我一次"的语音交互（"5分钟后提醒我"）

#### 创新 5：模糊时间理解

**支持的中文时间表达**（NLU 实体识别）:

| 表达类型 | 示例                    |
| ---- | --------------------- |
| 相对日期 | 今天、明天、后天、大后天、昨天       |
| 相对周  | 这周、下周、下下周、上周          |
| 相对日  | 前天、昨天、今天、明天、后天        |
| 星期表达 | 周一、星期二、礼拜三、周三         |
| 月度表达 | 下个月、上个月、这个月底          |
| 模糊时间 | 早上、上午、中午、下午、晚上、半夜     |
| 精确时间 | 3点、3点半、15:00、下午3点     |
| 复合表达 | 下周三下午、明天上午10点半、5月最后一天 |
| 时段表达 | 3点到4点、3-4点、3小时        |

### 4.2 请求流程图（核心场景）

```
场景: 语音创建事件 "明天下午3点开会"

用户 ──[语音]──→ 前端录音 (MediaRecorder)
                    │
                    ├──→ PCM/WAV 编码
                    │       │
                    │   WebSocket 发送音频流
                    │       │
后端 VoiceController ←──────┘
    │
    ├──→ 调用阿里云 ASR API → "明天下午3点开会"
    │
    ├──→ NluService.parse(text)
    │       ├── LLM 解析: { intent: "CREATE", title:"开会", time:"明天15:00" }
    │       └── 规则兜底校验
    │
    ├──→ EventService.createEvent(event)
    │       ├── 冲突检测 → 无冲突
    │       └── MySQL INSERT
    │
    ├──→ WebSocket 广播事件变更
    │       └── 前端 FullCalendar 实时更新
    │
    └──→ 返回结构化结果
            │
前端 ←────────┘
    │
    ├──→ 日历高亮显示占位
    ├──→ TTS: "您要在明天下午3点创建会议，确认吗？"
    └──→ 用户说"确认" → 最终提交
```

### 6.2 核心表 DDL

```sql
-- ============================================
-- 用户表
-- ============================================
CREATE TABLE users (
    id            BIGINT AUTO_INCREMENT PRIMARY KEY,
    username      VARCHAR(50) NOT NULL UNIQUE,
    password      VARCHAR(255) NOT NULL,
    display_name  VARCHAR(100),
    created_at    DATETIME DEFAULT CURRENT_TIMESTAMP,
    updated_at    DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

-- ============================================
-- 日历事件表（核心表）
-- ============================================
CREATE TABLE events (
    id            BIGINT AUTO_INCREMENT PRIMARY KEY,
    user_id       BIGINT NOT NULL,
    title         VARCHAR(500) NOT NULL COMMENT '事件标题',
    description   TEXT COMMENT '事件描述',
    start_time    DATETIME NOT NULL COMMENT '开始时间',
    end_time      DATETIME NOT NULL COMMENT '结束时间',
    all_day       TINYINT(1) DEFAULT 0 COMMENT '是否全天事件',
    location      VARCHAR(255) COMMENT '地点',
    color         VARCHAR(7) DEFAULT '#3788d8' COMMENT '显示颜色 #HEX',
    status        TINYINT DEFAULT 0 COMMENT '状态: 0=正常 1=已取消 2=已完成',
    reminder_min  INT DEFAULT 15 COMMENT '提前多少分钟提醒',
    repeat_rule   VARCHAR(500) COMMENT 'RRULE 重复规则',
    created_at    DATETIME DEFAULT CURRENT_TIMESTAMP,
    updated_at    DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    INDEX idx_user_start (user_id, start_time),
    INDEX idx_user_status (user_id, status),
    CONSTRAINT fk_event_user FOREIGN KEY (user_id) REFERENCES users(id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='日历事件表';

-- ============================================
-- 语音操作日志表（用于调试和 NLU 优化）
-- ============================================
CREATE TABLE voice_logs (
    id            BIGINT AUTO_INCREMENT PRIMARY KEY,
    user_id       BIGINT NOT NULL,
    raw_text      TEXT NOT NULL COMMENT 'ASR 识别文本',
    intent        VARCHAR(50) COMMENT '解析意图: CREATE/QUERY/UPDATE/DELETE',
    entities      JSON COMMENT '抽取的实体 {title, time, date, ...}',
    success       TINYINT(1) DEFAULT 1 COMMENT '是否处理成功',
    error_msg     VARCHAR(500) COMMENT '错误信息',
    duration_ms   INT COMMENT '处理耗时(毫秒)',
    created_at    DATETIME DEFAULT CURRENT_TIMESTAMP,
    INDEX idx_user_date (user_id, created_at),
    CONSTRAINT fk_vlog_user FOREIGN KEY (user_id) REFERENCES users(id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='语音操作日志表';
```

## 9. NLU 意图识别方案

### 9.1 双引擎架构

```
用户语音 → ASR → 文字
                  │
          ┌───────┴───────┐
          │               │
    ┌─────▼─────┐   ┌─────▼─────┐
    │  LLM 解析  │   │ 规则引擎   │
    │ (主力)     │   │ (兜底)     │
    └─────┬─────┘   └─────┬─────┘
          │               │
          └───────┬───────┘
                  │
          ┌───────▼───────┐
          │  结果合并器    │
          │  • 优先用 LLM │
          │  • LLM 失败   │
          │    用规则      │
          │  • 都失败→澄清 │
          └───────────────┘
```

### 9.2 规则引擎正则示例

```java
// CREATE 意图
Patterns:
  "^(?:创建|添加|新增|安排|计划)(?:一个|一条|个)?(?:事件|日程|会议|活动|提醒)?(.+?)(?:在|于)?(.+?)$"
  Example: "创建明天下午3点开会"
  → 捕获组1: "明天下午3点"
  → 捕获组2: "开会"

// QUERY 意图
Patterns:
  "^(?:查看|查询|看看|显示|帮我查)(?:一下|)?(.+?)(?:的)?(?:日程|安排|事件|活动|会议)?$"
  Example: "查看这周的安排"
  → 实体: { date_range: "这周" }

// UPDATE 意图
Patterns:
  "^(?:把|将)(.+?)(?:改成|改为|改到|调整到|改在|移到)(.+?)$"
  Example: "把明天的会议改到周四"
  → 捕获组1: "明天的会议"
  → 捕获组2: "周四"

// DELETE 意图
Patterns:
  "^(?:删除|取消|移除|去掉|删掉)(.+?)(?:事件|日程|会议|活动|提醒)?$"
  Example: "删除周五的例会"
  → 捕获组1: "周五的例会"
```

### 9.3 LLM 提示词模板

```text
你是一个日历助手的 NLU 解析引擎。请从用户的自然语言指令中提取意图和实体。

可用意图:
- CREATE: 创建新事件
- QUERY: 查询事件
- UPDATE: 修改事件
- DELETE: 删除事件
- REMINDER: 设置提醒

请返回 JSON 格式:
{
  "intent": "意图类型",
  "confidence": 0.0~1.0,
  "entities": {
    "title": "事件标题(如有)",
    "start_time": "开始时间(ISO格式, 自动计算相对日期)",
    "end_time": "结束时间(ISO格式, 默认为开始后1小时)",
    "location": "地点(如有)"
  }
}

用户指令: {用户输入}
```

### 10.3 集成方案（阿里云 ASR 示例）

// VoiceService.java — 阿里云 ASR 调用
public String speechToText(byte[] audioData) {
    // 1. 构建请求
    RecognizeRequest request = new RecognizeRequest()
        .setFormat("wav")
        .setSampleRate(16000)
        .setEnableIntermediateResult(false)
        .setAudioData(audioData);

    // 2. 调用 SDK
    RecognizeResponse response = client.getRecognizeClient()
        .recognize(request);

    // 3. 返回识别文本
    return response.getResult();
}

## 13. 最佳实践清单

### 13.1 通用最佳实践

| #   | 实践         | 说明                      |
|:---:| ---------- | ----------------------- |
| 1   | **渐进式交付**  | 先做核心闭环（创建事件），再扩展周边功能    |
| 2   | **日志驱动优化** | 记录每条语音操作日志，用于 NLU 持续改进  |
| 3   | **降级设计**   | 语音不可用时降级到文本输入，保证可用性     |
| 4   | **隐私优先**   | 录音不上传第三方，仅发送 ASR 所需音频   |
| 5   | **保持简单**   | 语音指令先覆盖 80% 的常见场景，再处理长尾 |

### 13.2 后端最佳实践

| #   | 实践           | 说明                            |
|:---:| ------------ | ----------------------------- |
| 1   | **统一响应格式**   | 所有 API 返回 `ApiResponse<T>` 结构 |
| 2   | **参数校验**     | 使用 `@Valid` + `@NotNull` 等注解  |
| 3   | **事务管理**     | `@Transactional` 保证数据一致性      |
| 4   | **异步处理**     | ASR/TTS 调用使用 `@Async` 避免阻塞    |
| 5   | **限流保护**     | ASR 接口做限流，防止恶意调用超额度           |
| 6   | **异常统一处理**   | `@ControllerAdvice` 全局异常拦截    |
| 7   | **SLF4J 日志** | 统一使用 logback 输出结构化日志          |

### 13.3 前端最佳实践

| #   | 实践                  | 说明                                     |
|:---:| ------------------- | -------------------------------------- |
| 1   | **Composition API** | 使用 `<script setup>` + composables 组织逻辑 |
| 2   | **TypeScript 严格模式** | 启用 `strict: true`                      |
| 3   | **组件单向数据流**         | Props 下传，Events 上传                     |
| 4   | **WebSocket 心跳保活**  | 每 30s 发一次心跳，60s 无响应自动重连                |
| 5   | **录音超时保护**          | 最长录音 60s，超时自动停止                        |
| 6   | **音频格式统一**          | 使用 16kHz 16bit PCM 或 WAV               |
| 7   | **请求防抖**            | 避免短时间内重复发送相同指令                         |
| 8   | **移动端适配**           | 响应式布局，触摸友好                             |

### 13.4 语音交互最佳实践

| #   | 实践        | 说明                         |
|:---:| --------- | -------------------------- |
